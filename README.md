# EIAF: Tamper-Evident Audit Framework for Multi-Centre Medical Data Platforms

EIAF (Edge-Immutability Audit Framework) implements a tamper-evident audit-logging
pipeline for multi-centre intelligent medical platforms. It combines four
deterministic compliance rules (minimum-necessary, cross-border de-identification,
unmasked export, and revoked-account login) with a SHA-256 chained credential
ledger signed by the Chinese national cryptographic standard SM2, plus a local
LSTM risk-inference model for runtime anomaly scoring.

> This repository is a **methodology / reproduction package** accompanying the
> manuscript submitted to **SoftwareX**. The audit corpus is **synthetic**: every
> number reported in the paper is computed on the fly from an 800,000-row synthetic
> CSV generated by `data/generator/gen_lecheng_logs.py`. This is not a hospital
> production platform and no real patient data is included.

## Repository layout

## Quick start

```bash
# 1) Generate the 800k-row synthetic corpus (byte-level reproducible, seed 42)
python data/generator/gen_lecheng_logs.py \
    --out data/lecheng_security_logs_2024H1_pipeline10.csv \
    --no-clinical \
    --config data/generator/clinical_config.json

# 2) Precompute audit metrics (SM2-signed chain + 12 node chains)
AUDIT_RULESET=v1 python scripts/precompute_metrics.py \
    --csv data/lecheng_security_logs_2024H1_pipeline10.csv \
    --out results/metrics_live.json

# 3) Run unit tests (rules R1-R4, chain verification, SM2 signature checks)
python -m pytest tests -q

# 4) Train the local LSTM risk-inference model
python scripts/train_lstm.py \
    --csv data/lecheng_security_logs_2024H1_pipeline10.csv \
    --window 24 --hidden 64 --max-train-seqs 120000 --epochs 8 --seed 42
```

Runtime dependencies: Python 3.10+, numpy, pandas, pytest, torch (CPU),
gmssl (SM2). Optional for the API backend: fastapi, uvicorn.

## Reproducibility

See [REPRODUCIBILITY.md](REPRODUCIBILITY.md) for the full record: corpus
fingerprints (sha256), environment notes, rule-hit statistics and the complete
reproduction workflow. The synthetic corpus is regenerable byte-for-byte by the
in-repo generator; the 23-column full version (which contains identifiable
fields) is intentionally **not** distributed.
